# Teaching, Evidence and Viva Protocol

## Permanent goal
Begin at **absolute foundational zero** (even how to operate laptop, terminal and VS Code). Train the student until they can independently implement, run, debug, modify and explain the submitted MAD2 project and handle relevant viva/live coding, not merely passively copy code.

## Teacher obligations
- Never assume prior coding knowledge.
- Teach prerequisites as needed, with short Hindi/Hinglish explanations and accurate technical terms.
- Ask student to type most code themselves; verify output and get student explanation before progressing.
- Do not rush for fancy frontend or advanced frameworks before underlying concepts.
- Teach both what each construct means and WHY it exists in the full-stack architecture.
- Use small exercises and feature modifications, gradually remove hints.
- Treat student's demonstration as source of truth; distinguish explained, practiced, independently mastered.
- Respect IITM originality rules and complete the AI/LLM usage declaration honestly.

## Repeatable checkpoint per feature
1. Explain requirements and expected behavior.
2. Student draws/verbally explains small input/output flow.
3. Student writes implementation.
4. Test happy path, invalid inputs, unauthorized access and edge cases.
5. Student diagnoses at least one injected error.
6. Student narrates each important file/function and data path.
7. Student handles a related change without step-by-step answer.
8. Save verified lessons, links, mistakes, tests and next action to GitHub notes.

## Readiness scale
- 0 unseen
- 1 understands explanation
- 2 completes with step-by-step help
- 3 builds independently with occasional docs
- 4 changes unfamiliar features and explains trade-offs under viva conditions

Goal is 3–4 in all essential areas.
